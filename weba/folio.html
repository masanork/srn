Web/A Folio: Separating Data from Intelligence

2025-12-27 By Sorane Project

Not a Wallet, but a Folio.

Web/A Folio is a concept for a "storage area for user data" within the Web/A Form ecosystem. It acts as a user-sovereign data container that integrally manages personal activity history, created documents, and identity-proving keys, moving beyond the financial focus of a traditional "digital wallet."

Concept: Loose Coupling of Data and Intelligence

The core of Web/A Folio is the complete separation of "Data (Folio)" and "Intelligence (Agent)."

  • The Folio (Data): Static, persistent assets. Existing as a "simple folder" on the user's PC or cloud storage. Not locked into any specific vendor or app.
  • The Agent (Intelligence): Dynamic, replaceable intelligence. You "hire" the best AI for the job (Gemini, Claude, GPT, or a local LLM), giving it temporary access to your Folio to complete tasks.

Users carry their Folio and can swap Agents as needed.

Principles: Human-Readablity and Machine-Programmability

Following the Web/A philosophy, every file in a Folio should be both "Human-Readable" and "Machine-Programmable."

  • No Black Boxes: Avoid proprietary binary formats or developer-only JSON/XML configurations where possible.
  • HTML as a Container: Profiles and certificates are primarily HTML files that can be viewed as "ID cards" or "certificates" in a browser. They embed structured data (JSON-LD) for Agent readability.

Philosophy: "User-as-a-Hub" Integration

Instead of complex API-to-API integrations that create an exponential web of dependencies, Web/A Folio proposes an architecture where the User is the hub of data integration.

  1. O(N) Connectivity: Services only need to output data to the Folio or read from it. No direct peer-to-peer service integration is required.
  2. Consent & Agency: Data flows through the user's hands. The user reviews, signs, and hand-delivers evidence.
  3. AI Readiness: It is easier for AI to "read a document" in a folder than to learn thousands of proprietary APIs.

Expected Structure

A Folio is expected to have the following structure on the file system:

MyFolio/
├── .index/            # [Optional] Search indices or vector DBs for AI agents (cache)
├── profile.html       # Basic identity. Looks like a business card or ID in a browser.
├── keys/              # Public keys and certificates for signing.
├── history/           # Past Web/A Forms. All viewable HTML.
│   ├── 2024-01_workcert.html
│   └── 2023-03_tax_return.html
├── certificates/      # VCs issued by third parties.
│   ├── degree.html
│   └── residence.html
└── inbox/             # Empty forms to be processed.
    └── new_application_form.md

Workflow: Agent-Assisted Filing

  1. Throw in: Drop an empty Web/A Form into the inbox/.
  2. Attach Agent: Grant an AI Agent access to the Folio.
  3. Context Retrieval: The Agent reads from history/ and certificates/ to understand your context.
  4. Auto-Fill: The Agent pre-fills the form based on your history.
  5. Sign & Verify: You review the result and sign it using keys in the Folio (e.g., via Passkeys).

Identity: Passkeys x National ID

Web/A Folio adopts a model that combines the hardware security of Passkeys (WebAuthn) with the legal certainty of National IDs.

  1. Generate Passkey: Create a local keypair on your device.
  2. Identity Binding: Sign the Passkey's public key using a National ID certificate.
  3. Ownership VC: Store a "Self-Signed VC" in the Folio that binds the Passkey to your legal identity.

This allows daily operations to be completed with simple biometrics while maintaining sovereign cryptographic proof of identity.
