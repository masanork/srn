Web/A Form Developer Guide

2025-12-30 By Sorane Project

Web/A Form is a serverless, file-based business application framework definable in Markdown. This document covers its architecture, source code structure, and the usage of development tools (Maker/CLI).

1. Architecture Overview

Web/A Form consists of three phases: Definition, Generation, and Runtime.

  1. Definition: Describe the form structure, input fields, and calculation formulas using a specialized Markdown syntax.
  2. Generation: Analyze the definition file and generate a single, self-contained HTML file (.html) incorporating CSS and JavaScript.
  3. Runtime: Opening the generated HTML file in a browser makes it function as an interactive form. Input data is embedded as JSON-LD, allowing for local saving and re-editing.

2. Directory Structure

Source code is centralized in src/form/, modularized for high maintainability.

File Role
src/form/parser.ts Markdown parser. Analyzes text and returns HTML fragments and metadata structures.
src/form/renderer.ts HTML renderer. Handles HTML string generation for each form component (Input, Select, Table, etc.).
src/form/generator.ts Integration module for generating complete HTML files. Embeds CSS and the Runtime Script.
src/form/cli.ts CLI tool. Converts Markdown files to Web/A Form (HTML) from the command line.
src/form/browser_maker.ts Entry point for the Web/A Maker (browser-based editor).
src/form/weba.test.ts Regression test code for the modules above.

3. Development Workflow

The project uses the Bun runtime.

3.1 Install Dependencies

bun install

3.2 Run Tests

Always run regression tests during development to ensure no impact on existing features.

bun test src/form/weba.test.ts

3.3 Building the Browser Maker

Bundle src/form/browser_maker.ts to generate mkform.js, which is loaded by the Web/A Maker (sites/srn/static/maker.html).

# Production build (used by GitHub Pages)
bun run build:srn

3.4 Using the CLI Tool

The CLI tool is useful for verifying behavior during development or generating forms in batches.

# Basic usage
bun src/form/cli.ts input.md > output.html

4. Layer 2 Encryption (L2E)

To enable L2 encryption, add the following to the Markdown Frontmatter:

---
layout: form
l2_encrypt: true
l2_recipient_kid: "issuer#kem-2025"
l2_recipient_x25519: "<base64url>"
# l2_recipient_pqc: "<base64url>" # Optional. ML-KEM-768 public key (Hybrid)
# l2_campaign_id: "campaign-1"
# l2_key_policy: "campaign+layer1" # Optional. campaign | campaign+layer1
# l2_layer1_ref: "sha256:..."
l2_encrypt_default: true
l2_user_kid: "user#sig-1"
---

Use l2_recipient_pqc for PQC/Hybrid mode. If omitted, only X25519 is used.

4.1 Root Key Derivation

Organizational root keys can be deterministically derived from the SRN instance key.

org_root_key = HKDF(srn_instance_key, info = "weba-l2/org-root" || org_id)

CLI example:

bun src/bin/weba-l2-crypto.ts gen-instance-key --out ./keys/srn-instance.json
bun src/bin/weba-l2-crypto.ts derive-org-root --instance-key ./keys/srn-instance.json --org-id org-1 --out ./keys/org-root.json

5. Excel-to-Form Migration Workflow

Since mechanical full conversion from Excel is difficult, we use a semi-automated MarkItDown + LLM workflow.

  1. Convert Excel to Markdown: Use Microsoft's markitdown or similar.
    • Example: markitdown input.xlsx > input.md
  2. Clean up Markdown: Organize headers, remove redundant lines, and check table structures.
  3. LLM Mapping: Use the conversion prompt in sites/srn/content/weba/prompt.md to map content to Web/A syntax.
  4. Generate HTML: bun src/form/cli.ts converted.md > output.html
  5. Quality Assurance: Verify layout, calculations, validation logic, and JSON-LD integrity.
