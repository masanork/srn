## 1. 概要

現代のデジタル化において、システム同士を連携させる際の最大の障壁は「接続コスト」です。本稿では、現在主流の **API Economy（API連携モデル）** と、Web/Aが提唱する **Document Economy（検証可能ドキュメント・モデル）** において、世界中のシステムを繋ぐのにかかる費用がどのように変化するかを、具体的なシナリオに基づいて試算します。

## 2. API Economy の限界：N^2 の接続爆発

API Economy では、データを持つシステム（Sourcing System）とデータを利用するシステム（Consuming System）が、互いにインターフェースを定義し、認証を通し、死活管理を行う必要があります。

### 2.1. 1接続あたりのコスト内訳（推計値）
1つのAPI連携を安全に構築・維持するために必要なコストは、組織間連携の場合、以下のようになります。

1.  **要件定義・設計**: スキーマのマッピング、業務フローの調整（100万円〜）
2.  **認証・セキュリティ**: OAuth等の実装、IP制限、鍵管理（50万円〜）
3.  **開発・検証**: APIクライアント/サーバーの実装、疎通テスト（200万円〜）
4.  **保守・運用**: バージョン更新追随、ダウンタイム対応（年50万円〜）
5.  **法務・契約**: 接続契約、SLA締結、データ利用ポリシー（50万円〜）

**合計（初年度）: $\approx$ 450万円 / 接続**

### 2.2. N対M の接続数爆発
組織数（または拠点数）が増えるにつれ、接続数は指数関数的に増大します。
1,000の組織が互いにデータをやり取りする場合：
- **最大接続数**: $1,000 \times 1,000 = 1,000,000$ 接続
- **現実世界での解決策**: 巨大なプラットフォーム（Hub）への集約
    - **新たなコスト**: プラットフォーム利用料（Rent）、データ主権の喪失、単一障害点リスク。

## 3. Document Economy：N + M の疎結合モデル

Web/Aが提唱するモデルでは、発行者は「検証可能なファイル」を出力し、検証者は「標準的な検証ルール」に従ってファイルを確認するだけです。システム同士が直接繋がる必要はありません。

### 3.1. 導入コストの構造（Web/Aモデル）
1.  **発行側のコスト (N)**: 自社システムからWeb/A形式でエクスポートする機能を実装。
    - 標準SDK利用により、一回限りの実装コストのみ。
2.  **検証側のコスト (M)**: Web/A形式を読み取り、真正性を検証する機能を実装。
    - ブラウザや汎用ライブラリが検証を肩代わりするため、実装負荷は極めて低い。
3.  **連携のコスト**: **0円**。ファイルという「共通のメディア」を介すため、相手が誰であっても個別の接続作業は発生しません。

## 4. 比較試算：1,000組織を繋ぐシミュレーション

1,000のシステムを相互に接続可能にするための「社会全体の総コスト」を試算します。

| 項目 | **API Economy (P2P/Mesh)** | **Document Economy (Web/A)** |
| :--- | :--- | :--- |
| **接続ロジック** | 密結合（相手ごとに定義） | 疎結合（標準に基づき独立） |
| **接続数/実装数** | **1,000,000 単位** (Mesh) | **2,000 単位** (Node実装のみ) |
| **初期コスト推計** | 4.5兆円 (4.5M円 × 1M接続) | **10億円** (0.5M円 × 2,000実装) |
| **保守コスト (年間)** | 5,000億円 (0.5M円 × 1M) | **1億円** (運用コストほぼゼロ) |
| **AI親和性** | 各APIごとに学習/マッピング | **全ドキュメント共通** |
| **結論** | **不可能（中央集権化が必須）** | **自律分散的に成立可能** |

*※推計値は組織間連携における平均的な工数に基づく。*

## 5. Document Economy がもたらす「接続コストの革命」

この試算が示すのは、ドキュメントをベースとした「疎結合な信頼」への移行が、単なる技術の選択ではなく、**「デジタル化の経済性」を数千倍に高める戦略**であるということです。

### 5.1. 接続コストが「ゼロ」に近づく世界
Web/Aという「自己記述的な証拠」が普及することで、以下の変化が起こります。

1.  **ロングテールのデジタル化**: コストが見合わずにAPI化を諦めていた「小さな証票」や「地方自治体の手続き」が、一気にデジタル・エコシステムに統合されます。
2.  **AIエージェントの解放**: AIは各社独自のAPIの仕様変更に怯えることなく、「目の前のWeb/Aファイル」を信頼できるデータソースとして即座に処理可能になります。
3.  **システム更改の自由**: バックエンドシステムをいつ入れ替えても、発行済みの証跡データはWeb/Aとして永続し、検証可能性を保ち続けます。

## 6. 結言

API連携は「線」の結合であり、その複雑さはネットワークの拡大と共に維持不能になります。対して検証可能ドキュメントは「点」の自立であり、標準さえあれば宇宙のように無限に拡張可能です。

Web/Aは、接続に費やしていた莫大なコストを、**「価値の創出」と「ユーザー体験の向上」**へ取り戻すためのインフラなのです。
